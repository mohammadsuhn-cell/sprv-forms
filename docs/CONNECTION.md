# Optional general-supervisor connection

26 September 2026. Activated devices can send saved forms to the separate sprv receiver. Existing unactivated browsers remain local. The static GitHub site does not store submissions or contain real student lists.

Open the personal activation link supplied by the general supervisor, review the assigned name and grade, and select **تفعيل الاتصال**. The link is valid for one device and 30 minutes. No phone app or VPN installation is required when the receiver has a public HTTPS tunnel address.

Continue using the same forms workspace after activation. It preserves the roster, saved forms and drafts already in that browser. Activation is a delivery identity, not a new isolated account: older saved forms keep their recorded authors and do not upload automatically. Explicitly saving an older unconnected form afterward assigns the activated identity and queues that saved version. Each supervisor should use their own browser storage; activation does not hide existing local history from someone sharing a browser.

In the local inbox, **عنوان الاستقبال** is the laptop's receiving address. Share the personal link generated by **رابط تفعيل جهاز**, which opens this forms site, rather than the receiving address itself. Another phone/browser needs a new link under the same supervisor; daily reuse needs no new activation.

- **حفظ** persists the form and queues its delivery. Draft autosaves and PDF/Word/Excel exports do not submit forms.
- Connection status appears only in **الإعدادات**. **تنزيل النسخة وإرسالها للإشراف العام** downloads the portable JSON and queues the exact same file for the supervisor inbox. This explicit action includes drafts, saved forms, roster and profile/settings; the button and note explain this. Backups up to 15 MB retry after offline reopening or lost responses without duplicate inbox copies. Settings shows their pending/received status. A failed queue operation does not undo the local download.
- **بانتظار الإرسال** means there is no confirmed receipt for the current saved revision. **تم الاستلام** includes the laptop's receipt time in Kuwait time.
- The phone retries on open, visibility/online events, and every 15 seconds while visible. If the laptop is off, reopen the forms when it becomes available. The tunnel stores no pending mailbox for the app.
- **تحتاج مراجعة** identifies a rejected submission or version conflict. Inspect it under Settings; retry does not overwrite a conflicting server record.
- The activated name/grade are fixed connection identity. Devices can be revoked from the local app without deleting received history.
- Earlier saved records matching the activated supervisor's name/grade can be explicitly queued from Settings. They are not silently attributed to a newly activated identity.
- Deleting a local saved copy does not withdraw a queued or received submission. Retraction is not part of this pilot.
- The non-exportable signing key and queue live in IndexedDB, separately from portable JSON backups. Browser-data clearing removes them. Backup files preserve forms, drafts and roster; they do not authorize a replacement device.
- The local inbox offers a **نسخة احتياطية** filter and **تنزيل النسخة** action. Its downloaded file can be restored on another browser using Settings. A new browser still needs device activation; cross-device editing of received records still requires future reconciliation. Continuous roster/settings synchronization and filtered recovery from individual submissions remain future work.

The public receiver accepts signed submissions, activation requests, and scoped signed reads for student histories. The local app's administration and personal register remain on loopback. A delivery receipt is issued after the SQLite transaction commits. Repeated delivery returns the same receipt; received revisions retain their history. A second device cannot overwrite the first device's record without a future reconciliation workflow.

**سجل الطالب** opens the receiver's student directory. Activated supervisors see only their assigned grade, including received reports from other supervisors of that grade. Selecting a student shows case-report counts, distinct late days and an expandable, paged history. A roster-selected student in a case or lateness form also has a history button; returning preserves the draft. Late-day totals use current received lateness forms and count each date once, even when multiple supervisors report it. Shared history is fetched on demand, kept only in page memory, and excluded from local saved forms and backups. Use **تحديث السجل** for newer receipts. A connection error is never presented as an empty history.

The matching receiver must support roster aliases, paged summaries/totals, single-report reads and five-minute signed-read freshness. Update/restart the receiver before publishing this forms change. A read-only general-supervisor identity can browse student histories across grades; its overview dashboard is not implemented yet.

Student history offers PDF, Word and Excel exports. **تصدير سجل الطالب الكامل** fetches a fresh unfiltered snapshot and every continuation page, with case summaries, references, student-specific actions and distinct late dates. An incomplete or expired read produces an error rather than a partial file. Each expanded case has **تصدير الحالة**, using the same exporters as saved cases, preserving the original author, reporting teacher, participants, pending actions and receiver reference. Downloads and sharing use the existing file controls, displayed inline in history. Shared data is not copied to saved forms or backups. The receiver must include `summaryVersion: 1` and case summaries in history responses, and the authorized case form in case-detail responses; update/restart it before publishing these controls.

Case receipts now include a permanent `CASE-YYYY-NNNNNN` number assigned by the receiver across all supervisors. It appears on the phone and in case exports, remains unchanged across corrections and retries, and is included in downloaded backups. Before delivery the case shows **بانتظار رقم الحالة**. Older acknowledged cases can retrieve their reference on reopening the updated forms without creating another case or revision. Receivers must be updated before publishing this phone feature.

Implementation: `src/delivery.js`, `src/delivery-ui.jsx`. Device authentication uses WebCrypto ECDSA P-256. Connection tests run from the sibling sprv repo with synthetic data: `npm run check:connection`. The normal forms/export checks also verify unactivated operation stays local.

Live pilot, 26 September 2026: public HTTPS/CORS and access restrictions passed; the user activated their phone through an inbox-generated link, and a saved late-students form reached the local inbox with a receipt. The received form was included in a validated local ZIP. Carrier-data-only and physical-phone offline/reopen checks remain rollout checks; this first receipt does not establish those conditions.
